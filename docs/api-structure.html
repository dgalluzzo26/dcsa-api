DCSA API structure

A new report is a YAML key. Identity is the POST body. Everything else is assembled from config at startup.

report_code lives in the path. The body is ssn / name+DOB / candidate_id only.

What a caller hits

flowchart LR
  client[Caller]
  post["POST /api/v1/requests/{report_code}"]
  get["GET /api/v1/requests/{report_code}/{id}"]
  body[Identity body]
  env[Typed envelope]
  client --> post
  client --> get
  post --> body
  post --> env
  get --> env

How a request is assembled

Startup: ready_report_models() walks reports: in config.yaml, types each data section from SECTION_ROW_MODELS[source], and registers POST/GET. No per-report Python file. 

flowchart TB
  route[fpvr routes]
  svc[FPVRRequestService]
  ident[Identity lookup]
  asm[ReportAssembler]
  log[Request log]
  job[Optional Databricks job]
  route --> svc
  svc --> ident
  svc --> asm
  svc --> log
  asm -->|ready or pending| svc
  svc -->|pending and on_pending| job
  yamlReports["config.yaml reports"]
  yamlSources["config.yaml sources"]
  mapping[mapping.yml]
  rows[SECTION_ROW_MODELS]
  yamlReports --> route
  yamlReports --> asm
  yamlSources --> ident
  yamlSources --> asm
  mapping --> asm
  rows --> route

Who owns which contract

flowchart TB
  subgraph yaml ["config.yaml"]

  end
  subgraph map ["mapping.yml"]
    rename["lake column to API name / omit"]
  end
  subgraph py [Python]
    row[report_contract row models]
    factory["registry create_model"]
    sql["parameterized SELECT"]
  end
  src --> sql
  src --> rename
  rename --> row
  rpt --> factory
  row --> factory
  jobs --> rpt
Question Answer comes from
Which reports / HTTP paths exist? config.yaml reports:
Which tables and selected columns? config.yaml sources:
JSON field names on a row? mapping.yml
Types on a row? SECTION_ROW_MODELS (must match mapping)
Keys under report.data? YAML section names
Existing-source report Add one reports: entry, restart.
New source sources: + mapping.yml + a row model, then the report entry.
