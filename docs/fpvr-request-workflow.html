FPVR request API workflow

DCSA API on Databricks Apps. Callers authenticate with client id and secret, open an official request for one FPVR report, poll until ready, then fetch the payload. Request logging uses the app service principal; report data is queried on-behalf-of the caller so Unity Catalog ABAC and RBAC apply.

Caller flow

Machine-to-machine. Token is OAuth2 client credentials, then three HTTP calls. Entity resolution happens inside the request API, before an official request id is issued.

StepCallSuccessOtherwise
1. Auth POST {workspace}/oidc/v1/token (HTTP Basic client_id:client_secret) Bearer token 401 invalid credentials
2. Request POST /api/v1/requests 200 + request_id (unique subject) 409 candidates without SSN, or 404 none
3. Status GET /api/v1/requests/{id} pending | ready | failed 403/404 if not the caller’s request
4. Response GET /api/v1/requests/{id}/response Report JSON (OBO query) 409 if not ready; empty/denied if ABAC hides rows

Entity resolution before an official request

No subject 0 matches

HTTP 404. Nothing is written to the request log. Caller must tighten or correct identity fields.

Ambiguous 2+ matches

HTTP 409. Return candidate list without SSN (name, DOB, place of birth, sex, citizenship) plus an opaque candidate_id. No request id yet. Caller resubmits with candidate_id or more filters.

Official request 1 match

HTTP 200. App SP inserts a request row, generates request_id, stores report code, caller identity, timestamps. Status starts pending or ready depending on whether the report is in-lake.

Auth and identity split

Token (caller)

OAuth2 client_credentials against the Databricks workspace (service principal client id and secret). Use that Bearer on every API call. Do not mint a custom token store.

The same token is the OBO credential for SQL Statement Execution when serving the report.

Who runs which SQL

App SP: INSERT/UPDATE on the request log table only (audit must always land).

Caller OBO: SELECT on subject_* tables when assembling a ready response, so row filters, column masks, and grants apply.

Proposed modules

models

RequestCreate, Candidate, RequestAccepted, RequestStatus, Report payload schemas per FPVR code.

services

EntityResolutionService (OBO identity lookup), RequestLogService (App SP), ReportAssemblerService (OBO).

routes

POST /requests, GET /requests/{id}, GET /requests/{id}/response. Keep existing /health and /me. Token from workspace POST /oidc/v1/token, not this app.

Pending reports in this mock can flip to ready on a status poll by re-checking the lake (no external fetch yet). That keeps the poll contract without a job queue. A later worker can update status asynchronously using the same request_id.
